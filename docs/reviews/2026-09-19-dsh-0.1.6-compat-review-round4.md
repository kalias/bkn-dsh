**本轮修复明显收敛，但 Windows 测试与路径清洗尚未闭环，不建议宣告跨平台发布就绪。**

## 4. 待修复发现

### F1 [P1] Windows 路径清洗测试仍生成非法 JSON

**位置**：`tests/bundle-portability.test.mjs:200–207`。

当前 fixture：

```js
writeFileSync(join(root, 'a.map'), `{"sources":["${join(home, 'x.ts')}"]}`)
```

改用原生 `join()` 修复了先前路径比较问题，但把 Windows 路径直接插入 JSON 文本没有进行 JSON 转义。

Windows 原生路径例如：

```text
C:\Users\builder\x.ts
```

经 `scrubAbsolutePaths` 删除 home 前缀后，原始 JSON 文本等价于：

```json
{"sources":["\x.ts"]}
```

其中 `\x` 不是合法的 JSON escape，因此测试在第 206 行 `JSON.parse(...)` 失败。使用 path.win32 与实际清洗函数的内存探针已复现。

**影响**：该测试不受 symlink 权限 skip 控制，Windows CI 执行 `tests/*.test.mjs` 时仍会失败。不能因其他跨平台 fixture 已修改就将 T1 全部关闭。

**修复建议**：

- 用 `JSON.stringify({ sources: [join(home, 'x.ts')] })` 创建有效 fixture。
- 同时修复 F2；只改 fixture 后，合法转义路径会暴露生产清洗没有生效的问题。
- 断言清洗后仍是有效 JSON，实际 sources 不再包含构建根，且完整 portability 检查通过。
- 不要仅将断言改为“没有抛异常”，也不要将 Windows 用例 skip 掉。

**验收标准**：

- Windows 原生该测试通过。
- 对 JSON 转义反斜杠、正斜杠两种合法路径形式分别验证“序列化 → 清洗 → 解析 → 门禁”全链路。
- macOS 回归保持通过。

### F2 [P2] Windows 路径清洗和路径检测契约不一致

**位置**：

- `runtime/bundle-portability.mjs:151–159`（scrubAbsolutePaths）。
- `runtime/bundle-portability.mjs:197–207`（扫描变体处理附近）。
- `runtime/assemble-compatible-runtime-bundle.mjs:117`（组装调用清洗）。

扫描器已支持原生/正斜杠 home，并扫描 JSON 反转义变体；清洗器仍只有：

```js
const roots = prefixes.map(value => resolve(value)).filter(Boolean)
// ...
if (updated.includes(prefix)) updated = updated.split(prefix).join('')
```

因此，同一个 Windows 源路径在合法 JSON 中表现为转义反斜杠，或者工具输出为正斜杠时，清洗不会命中。

实际函数的 win32 内存探针结果：

| 输入 | 清洗结果 | 门禁结果 |
| --- | --- | --- |
| JSON.stringify 序列化的原生 Windows 路径 | 保持原始构建根 | 拒绝：build-machine path |
| JSON 中的 C:/Users/builder/x.ts | 保持原始构建根 | 拒绝：build-machine path |

**影响**：门禁检测能力变强了，但正常规范化管线没有跟上；遇到这些常见合法格式时，Windows 构建仍无法交付。当前 macOS 产物通过不能证明 Windows 已解决。

**修复建议**：

- 明确支持的路径序列化格式，使清洗与检测共享一致的路径规范。
- 对 JSON/source map 的目标字段进行格式感知处理，避免全局反转义再重写破坏其他字符串。
- 对输出正斜杠的 Windows 工具也提供一致处理。
- 不要通过移除检测变体、忽略泄漏文件或吞掉门禁错误来修复。
- 路径被删掉并不自动等于资源引用可用；需要区分 source map 调试路径与真正运行时路径，继续保留后者的可解析性。

**验收标准**：

- 上述两类合法输入完成清洗后可解析且门禁通过。
- 对运行时代码、配置和 source map 分别有测试，确保非路径内容不受损。
- Windows 真实归档扫描无构建根残留；未获得此证据前明确标为未验证。
