## 6. 非阻断发现与建议

### N1 [P3] 回应中的 JSON 示例与路径性质不准确

**位置**：`docs/reviews/2026-09-19-review-response.md`，“第四轮审核回应”中 F2 的回归说明与设计取舍。

文档把清洗后的 Windows JSON 展示为 `{"sources":["\x.ts"]}` 并称有效。若按字面理解，该 JSON 中单个反斜杠接 x 是非法转义。

本轮实际输出的 JSON 文本是：

```json
{"sources":["\\x.ts"],"keep":"sentinel-not-a-path"}
```

JSON 文本中 x 之前有两个反斜杠；解析后的字符串才是单个反斜杠开头的 `\x.ts`。生产逻辑本轮通过解析，不能因为示例写错而误报代码仍有 F1。

另外，清洗后的 `/x.ts` 和 Windows 的 `\x.ts` 都是 rooted 路径形态，不是通常意义上的相对路径。移除构建前缀意味着调试来源降级，并不意味着路径已转换为可移植的相对资源引用。

**建议**：修正文档示例，明确区分序列化文本、解析后字符串、可解析资源路径；无需因此回退已经通过探针的代码修复。

### N2：测试覆盖建议（不列为已证实缺陷）

- 当前新增 fixture 在 macOS 中不自然产生 Windows 反斜杠；可以将本轮 win32/UNC 逻辑探针固化为纯测试，在没有 Windows 时也能覆盖这些分支。
- 测试末尾注释提到“清洗前会拒绝”，实际 fixture 用例没有显式执行清洗前断言。本轮独立探针已验证此前后行为，后续可加入 assert.throws，强化回归。
- Windows symlink 用例允许权限不足时 skip；发布验收应记录 skipped 数量，并至少在一个可执行这些测试的 Windows 环境验证。退出码 0 不等于所有用例实际执行。

### 保存后收到的具体门禁诊断（仍未解决）

最新诊断不再是此前的 unknown-return / unused-export，而是：

1. **scoped-business-context.ts:56**：`as unknown as DshSessionLog` 附近缺少 `SAFETY:` 注释。该定位与源码中的双重断言对应，是明确的规则合规项。后续开发应核实真实 session 对象满足 DshSessionLog 的哪些成员及生命周期不变量，优先消除不必要断言；若断言必要，记录 TypeScript 无法证明的真实依据，不得仅写空泛的“安全”声明。
2. **bootstrap-openbkn-plugin.mjs:16–17**：两处 JSON.parse 没有局部 try/catch，分别读取 profile 和 plugin manifest。解析损坏文件会抛错是已知行为；不能将其自动解释为运行时安全漏洞，也不能直接吞错并当作正常未安装。若该规则是必须通过的交付门禁，开发应保留失败关闭语义，补充上下文明确的解析错误处理，并测试损坏 JSON 不会覆盖既有 profile、不会继续启动。

自动工具对以上项标记 STOP；本轮未修改源码，因此门禁仍未关闭。它们是静态合规/失败路径待办，与 F1/F2 的路径算法修复结论分开记录。需在后续交付中明确处置，不应沿用本节此前对不同规则的判断。
