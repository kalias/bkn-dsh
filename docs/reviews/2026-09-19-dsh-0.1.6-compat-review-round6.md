## 4. 新增静态门禁待办（本轮收到，未处置）

保存报告期间自动诊断给出两条新的 STOP 级提示，均为**构建脚本的裸调用无 try/catch**：

1. `scripts/build-compatible-runtime.mjs:23` 附近——manifest 读取等调用未包错误上下文。
2. `scripts/package-bundle.mjs:22` 附近——同类裸调用。

**处理建议**：这两个是开发者 CLI 脚本，失败时直接抛错（fail-fast）对构建使用者通常可接受，与 bootstrap 面向最终用户的场景不同。但规则标记 STOP 即为交付门禁，需显式二选一：

- 按规则补上下文包装（对齐 bootstrap 的 readManifest 模式：错误消息指明是哪一步、哪个文件失败）；或
- 在规则配置中对该类构建脚本作有依据的豁免，并记录理由。

不应忽略提示直接交付，也不应机械套 try/catch 吞错。本轮未修改源码，门禁仍未关闭。
